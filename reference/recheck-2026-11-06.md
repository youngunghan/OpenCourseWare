- 근거: [NeRF README](https://github.com/youngunghan/OpenCourseWare/blob/74b5c42e11e2345e0a7acb1192143eaf933b7f82/materials/KAIST/KAIST-Visual-AI-Group__CS479-Assignment-NeRF/README.md), [PointNet README](https://github.com/youngunghan/OpenCourseWare/blob/74b5c42e11e2345e0a7acb1192143eaf933b7f82/materials/KAIST/KAIST-Visual-AI-Group__CS479-Assignment-PointNet/README.md), [PointNet LICENSE](https://github.com/youngunghan/OpenCourseWare/blob/74b5c42e11e2345e0a7acb1192143eaf933b7f82/materials/KAIST/KAIST-Visual-AI-Group__CS479-Assignment-PointNet/LICENSE).

### 2. 서울대 자료구조의 페이지와 파일 접근 상태를 분리해야 한다

`SNU-C005`의 기존 보관 상태는 접근 실패를 이유로 들지만, 카탈로그와 2026-11-04 재검토 기록에는 재접속 성공과 PDF 확인이 적혀 있다. 서로 다른 시점과 접근 대상을 하나의 상태로 합쳐 둬 해석이 모호하다.

2026-11-06 직접 재확인에서는 [진입 페이지](https://datalab.snu.ac.kr/~ukang/courses/26F-DS/)의 HTTPS 연결이 끊겼고 HTTP 대안도 시간 초과였다. 반면 [L1-intro.pdf](https://datalab.snu.ac.kr/~ukang/courses/26F-DS/L1-intro.pdf)는 **HTTP 206과 PDF 헤더**를 확인했다. 오늘의 확인은 최대 64KiB 표본 요청이며, PDF 전체를 새로 정독한 결과가 아니다.

- 영향: 진입 페이지 접속 실패가 수업 자료 전체의 부재나 모든 파일의 접근 실패를 뜻하지 않는다. 반대로 과거의 HTTP 200 기록만으로 오늘도 페이지가 정상이라고 단정할 수 없다.
- 수정안: 페이지와 개별 파일의 확인일·상태를 각각 기록하고, 재배포 허가 미확인과 접근 실패를 구분한다. 독립 검수는 과거 기록의 모순을 지적하며 허가 미확인으로의 단순 변경을 제안했으나, 오늘 페이지 접속 실패가 재현돼 그 변경을 그대로 적용하지 않았다.

```sh
git clone https://github.com/youngunghan/OpenCourseWare.git
cd OpenCourseWare
git show 74b5c42e11e2345e0a7acb1192143eaf933b7f82:reference/original-files.json
```

전체 요청 결과·원시 CLI 검수 출력·기존 무결성 검증 스크립트는 공개 저장소에 포함되지 않은 로컬 감사 근거다. 따라서 새 clone만으로 이번 자동 검증 전체를 그대로 재실행할 수는 없다. 공개 정본 JSON의 파일 경로·크기·SHA-256과 이 보고서의 확인 범위부터 대조하고, 우선 K004의 학기별 원본 여부와 C005의 접근 상태 기록을 정정하는 작업으로 이어간다. LMS 접근이나 원본 과제 코드를 실행하는 절차는 추가하지 않는다.
